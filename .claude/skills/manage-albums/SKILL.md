# manage-albums

Manage the music albums shown on the favorites page (`/favorites`). There are three operations: **add**, **remove**, and **rearrange custom order**. Pick the one the user asked for; if ambiguous, ask.

## Data model (the moving parts)

An album is spread across these files — the **album title is the contract** and must be byte-identical everywhere it appears:

- `src/data/favorite-albums.json` — the Spotify "pick": `{ title, artist, spotifyAlbumId?, featuredTrackNumber, favoriteTrackNumbers[] }`. Drives the sync script.
- `src/data/favorites.ts`:
  - `ALBUMS[]` — `{ src, title, artist, year, customorder }`. Hand-edited. `src` is a local path under `public/`.
  - `TRACKLISTS` — keyed by title. **Generated by the sync script; never hand-edit it for an add.**
  - `FEATURED_TRACK_AUDIO` — keyed by title → `{ <trackNumber>: <audioPath> }`. Optional, hand-edited.
- `public/images/favorites/albums/album-<...>.{jpg,png}` — the cover image. Committed to the repo (these are **not** in Supabase, unlike travels).

How the page uses it (`src/app/favorites/page.tsx`):
- The default sort is **`"added"` ("custom order")**, sorting `ALBUMS` by `customorder` **descending** — highest number shows first.
- The card label renders `REF. C-{customorder padded to 2}` (e.g. `customorder: 11` → `REF. C-11`).
- `customorder` is a **manual display ranking, not tied to age or release year**: higher number = shows first in the rack. The user decides each slot deliberately.

## Hard rules

- **Title is the contract.** The `title` in `favorite-albums.json`, `ALBUMS`, `TRACKLISTS`, and any `FEATURED_TRACK_AUDIO` key must match exactly (including punctuation, casing, and any non-Latin characters).
- **`customorder` values stay unique and contiguous `1..N`.** Never leave a gap or a duplicate — both break the `REF. C-NN` numbering and the sort.
- **Never hand-write `TRACKLISTS` when adding.** Edit `favorite-albums.json` and run `npm run sync:spotify-albums`; the script regenerates the whole `TRACKLISTS` block.
- **Never invent a cover filename.** The image must already exist in `public/images/favorites/albums/`. If it doesn't, stop and ask the user to add it.
- **Always ask where the album sits in the custom order** when adding (see below). Don't guess.

## Operation: ADD an album

### Inputs to collect (ask for any not provided)
- `title` — exact album title (becomes the cross-file key).
- `artist`.
- `year` — release year (drives the new↔old sorts and the `artist · year` line).
- `cover` — the filename already present in `public/images/favorites/albums/` (e.g. `album-charli-brat.jpg`).
- `customorder position` — **where it sits in the custom order.** Explain the scale: it's a manual display ranking, not age-based — `1` shows last in the rack, the current max (`N`) shows first. Ask for the integer slot `1..N+1` (top of the rack is `N+1`).
- `featuredTrackNumber` and `favoriteTrackNumbers[]` — for the Spotify pick (track highlighting). Optional but recommended.
- `spotifyAlbumId` — optional; provide it if the title/artist is ambiguous on Spotify (see step 4 caveat).

### Steps
1. **Verify the cover exists.** Confirm `public/images/favorites/albums/<cover>` is present. If not, stop and ask the user to add it first.
2. **Confirm the title isn't already in `ALBUMS`.** If it is, this is an edit, not an add — stop and clarify.
3. **Shift custom order to make room.** Let `P` be the requested slot. For every existing album with `customorder >= P`, increment its `customorder` by 1. Then the new album takes `customorder: P`. Result must be contiguous `1..N+1` with no duplicates.
4. **Add the Spotify pick** to `src/data/favorite-albums.json`: `{ "title", "artist", "featuredTrackNumber", "favoriteTrackNumbers": [...] }`. Add `"spotifyAlbumId"` if provided.
5. **Add the `ALBUMS` entry** in `src/data/favorites.ts`: `{ src: "/images/favorites/albums/<cover>", title, artist, year, customorder: P }`. (Array position is cosmetic — `customorder` controls display.)
6. **Run the sync** to fetch the tracklist:
   ```
   npm run sync:spotify-albums
   ```
   This rewrites the `TRACKLISTS` block from the picks. Read its console output:
   - If it errors about `SPOTIFY_CLIENT_ID`/`SPOTIFY_CLIENT_SECRET`, tell the user to add those to `.env.local` and stop.
   - If it warns the synced album/tracks look wrong (or the printed track count is off), the title/artist matched the wrong release — add the correct `spotifyAlbumId` to the pick and re-run.
7. **(Optional) featured-track audio.** If the user has an audio clip for the featured track, place it under `public/audio/favorites/` and add a `FEATURED_TRACK_AUDIO["<title>"] = { <featuredTrackNumber>: "/audio/favorites/<file>" }` entry. Skip if none.
8. **Gate** (below).

## Operation: REMOVE an album

### Inputs
- `title` — which album to remove (exact title).

### Steps
1. **Find its `customorder`** — call it `R`.
2. **Delete the pick** from `src/data/favorite-albums.json`.
3. **Delete the `ALBUMS` entry** from `src/data/favorites.ts`.
4. **Delete its `FEATURED_TRACK_AUDIO["<title>"]` entry** if one exists.
5. **Close the gap.** For every remaining album with `customorder > R`, decrement `customorder` by 1, so the set stays contiguous `1..N-1`.
6. **Regenerate `TRACKLISTS`.** Either re-run `npm run sync:spotify-albums` (authoritative — needs Spotify creds), **or**, if creds aren't available, hand-delete that title's block from the `TRACKLISTS` object in `src/data/favorites.ts`. Don't leave an orphaned tracklist.
7. **Leave the cover image and any audio file in place** unless the user explicitly asks to delete them (removing committed assets is harder to reverse — confirm first).
8. **Gate** (below).

## Operation: REARRANGE custom order

### Inputs
- The desired ordering — either explicit `title → customorder` assignments, or a ranked list (e.g. "make Brat the most recent"), or a couple of moves ("swap X and Y").

### Steps
1. Read the current `ALBUMS` `customorder` values.
2. Apply the requested change, then **renumber so the result is a contiguous unique `1..N`** (no gaps, no duplicates). Remember higher = shows first in the rack.
3. Edit only the `customorder` values in `src/data/favorites.ts`. No other file changes are needed (titles, picks, and tracklists are untouched).
4. Echo the resulting order back to the user (title + `REF. C-NN`) so they can confirm it matches their intent.
5. **Gate** (below).

## Gate (every operation)

Run the project's verification gate:
```
npx tsc --noEmit
npm run lint
```
Then summarize what changed. For add/remove, list the new contiguous `customorder` → `REF. C-NN` mapping so the user can eyeball it. Since this is a visual change, remind the user to check `/favorites` (the default "custom order" sort) at desktop and mobile, watching for the right album leading the rack and the correct `REF. C-NN` on the track-list card.

## Notes
- The sync script (`scripts/sync-spotify-albums.mjs`) only rewrites the `TRACKLISTS`…`DEFAULT_TRACKLIST` block. It does **not** touch `ALBUMS`, `customorder`, `FEATURED_TRACK_AUDIO`, or `MOVIES` — those are always hand-edited here.
- `customorder` is independent of release `year`. Don't assume the two correlate; the user sets custom order deliberately.
